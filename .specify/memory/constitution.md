# 云大射击训练预约与成绩管理小程序 — 项目宪法

> 本文件是项目的最高级原则性文件。所有规范（spec.md）、技术方案（plan.md）、任务清单（tasks.md）以及代码实现，均不得违背本宪法。

---

## 第一条 范围与优先级（MVP 优先）

1. V1.0 仅覆盖需求文档《射击训练预约与成绩管理小程序 v0.1》第三十章 MVP 范围。
2. 核心闭环：**注册 → 设备状态查看 → 预约 → 排队 → 签到 → 开始训练 → 结束训练 → 成绩记录 → 个人画像 → 排行榜**。
3. V2.0 功能（候补队列、信用分、智能推荐、利用率分析等）一律不进入 V1.0 范围；需求文档出现但 V1.0 不实现的功能，统一登记在 `docs/QAmd.md` 待后续版本决策。
4. 当 MVP 闭环未跑通前，禁止投入资源扩展 V2.0。

## 第二条 最高业务指标

**资源利用效率（Utilization）** 是 V1.0 最高业务指标：

```
设备利用率 = ∑(实际训练时长_min) / ∑(可预约时长_min)  其中 0 ≤ 利用率 ≤ 1
```

- 单位：百分比（保留 2 位小数）。
- 统计粒度：按设备 × 日期 × 时间片 三维聚合。
- 训练闭环、预约规则、设备状态推送均以提升该指标为设计导向。

## 第三条 作息时间片（标准不可配置）

下列 6 个时间片为云大射击训练馆的标准作息，**不在 V1.0 提供后台可配置入口**（参见 `docs/QAmd.md` Q2）：

| 编号 | 时间段          |
|------|-----------------|
| S1   | 08:30 – 10:10   |
| S2   | 10:30 – 12:10   |
| S3   | 14:00 – 15:40   |
| S4   | 16:00 – 17:40   |
| S5   | 19:00 – 20:40   |
| S6   | 21:30 – 22:30   |

- 特殊时段：管理员可手动追加"临时开放"时间片（参见 `docs/QAmd.md` Q10）。
- 不在任一时间片内且无临时开放的时段：**系统不开放预约**（无人值班即不安全）。

## 第四条 三角色与权限矩阵

1. 角色：`student`（学员）、`admin`（管理员）、`superadmin`（超级管理员）。
2. 用户与角色为 **N:M** 关系（同一用户可同时是学员 + 管理员）。
3. 权限矩阵：

| 资源/能力                              | student | admin | superadmin |
|----------------------------------------|:-------:|:-----:|:----------:|
| 微信登录 / 身份登记                    |    ✅   |  ✅   |     ✅     |
| 查看设备状态                            |    ✅   |  ✅   |     ✅     |
| 维护个人可训练时间                      |    ✅   |  ✅   |     ✅     |
| 提交 / 取消 / 签到 / 开始 / 结束 训练   |    ✅   |  ✅   |     ✅     |
| 查看自己个人画像与排行榜                |    ✅   |  ✅   |     ✅     |
| 排班（管理员值班时间）                  |    ❌   |  ✅   |     ✅     |
| 学员管理 / 录入成绩                     |    ❌   |  ✅   |     ✅     |
| 设备上下线 / 标记维护 / 停用            |    ❌   |  ✅   |     ✅     |
| 角色授权 / 超级管理员授予              |    ❌   |  ❌   |     ✅     |
| 数据备份与回滚                          |    ❌   |  ❌   |     ✅     |

## 第五条 隐私与脱敏红线

1. 普通学员**不得**查看其他学员的：`姓名`、`学号`、`联系电话`、`身份证号`。
2. 排行榜只展示 `昵称/化名 + 总分/环比`，禁止敏感字段出现在对其他学员可见的接口里。
3. 管理员侧接口可查看完整字段，但需在每次查询记录审计日志。
4. 客户端日志禁止打印 token、openid、密码（即使是 mock 登录）。

## 第六条 预约规则（规则引擎约束）

1. **每天至多 3 场**（同一学员同一日期 BOOKED/CHECKED_IN/IN_USE/COMPLETED 累计）。
2. **每周至多 10 场**（自然周）。
3. **最多提前 7 天**预约。
4. **取消分级**：距开始 ≥ 12 小时免费取消；< 12 小时记录"晚取消"；< 1 小时记录"临近取消"（爽约见第五条规则）。
5. 同一学员同一时间片不得重复预约。
6. 同一设备同一时间片不得重复预约（DB 唯一索引 + Redis 锁双保险）。
7. 设备 IDLE/BOOKED 可被预约；IN_USE/MAINTENANCE/DISABLED 不可。
8. 学员可训练时间 ∩ 管理员可值班时间 ∩ 设备可服务时间 **三者交集非空** 才允许预约。

## 第七条 训练闭环红线

1. 签到时间窗口：预约开始前 30 分钟 ～ 开始后 10 分钟。超时未签到 → 自动爽约。
2. 爽约记录：仅记录次数与时间，**V1.0 不设封禁阈值**（参见 `docs/QAmd.md` Q5）。
3. "提前结束"由学员自操作（参见 `docs/QAmd.md` Q6）。
4. 训练实际时长 = max(结束时间 − 开始时间, 1 分钟)，记录到 training_sessions 表。
5. 训练结束 → 状态机：BOOKED → CHECKED_IN → IN_USE → COMPLETED；任意环节失败 → CANCELLED / NO_SHOW。

## 第八条 技术栈（已更新 V1.0 实际栈）

| 层级       | V1.0 实际栈                                      | 备选生产栈              |
|------------|--------------------------------------------------|-----------------------|
| 后端框架   | Spring Boot 3.4 + JDK 21                         | Spring Boot 4.x（未来）|
| 数据库     | PostgreSQL 18（`localhost:5432` 已运行）           | MySQL（按需切换）       |
| 缓存/锁    | Redis 7（`redis-cli ping` → PONG，已运行）         | 同                    |
| 实时推送   | Spring WebSocket + STOMP                           | 同                    |
| 鉴权       | Spring Security + JWT（jjwt）                      | 同                    |
| ORM        | Spring Data JPA + Hibernate                        | 同                    |
| 构建       | Maven 3                                           | Gradle（按需）         |
| 小程序     | 微信原生（wxml/wxss/js）                           | 同                    |

**回退路径**：切换 JDBC URL 和方言即可换 MySQL；Spring Security 配置换 OAuth2 即可接微信 Auth；接口契约与数据模型保持不变。**接口契约 `docs/api.md` 与 JPA Entity 必须保持一致**。

## 第九条 代码质量基线

1. 单元测试覆盖：预约规则引擎、Redis 分布式锁、三交集匹配、爽约检测 → 必须 ≥ 80%（JaCoCo 报告）。
2. 所有 `@RestController` 必须有：请求体 `@Valid` 校验（Bean Validation JSR-380）、统一全局异常处理（`@RestControllerAdvice`）、JWT 校验（Spring Security Filter 白名单除外）。
3. 数据库迁移必须幂等（`flyway:baseline` / `schema.sql` + `CREATE TABLE IF NOT EXISTS`）。
4. 禁止 `raw Type` 滥用；PMD 默认规则集必须通过。
5. 提交前自检：`mvn test && mvn verify`。
