# 开发、部署与发布 v1.0.0

基线日期：2026-09-26。源码仓库、服务器 JAR 和微信小程序是三个独立发布对象。Git 推送不会自动更新后两者。

## 1. 环境与依赖

- Java 21、Maven；不要用本机默认较新的 JDK 替代验收环境，部分测试依赖对其他 JDK 的支持不同。
- Node.js 与 npm；本次验证使用 Node.js 24，前端通过 `package-lock.json` 固定依赖，仓库 `.npmrc` 保留安装兼容选项。
- Python 3 用于生成部署包；首次数据库部署需要 PostgreSQL 客户端。
- PostgreSQL 建表脚本面向 14+，本地隔离验证使用 18。微信开发者工具用于实际小程序编译与预览。

```bash
git clone https://github.com/LittBox/ynu-shooting-training.git
cd ynu-shooting-training
cd frontend
npm ci
npm test
cd ../backend-spring
mvn verify
```

后端真实 HTTP 集成测试会调用前端模块，先安装前端依赖。macOS 可在运行 Maven 前执行 `export JAVA_HOME=$(/usr/libexec/java_home -v 21)`；其他系统将 JAVA_HOME 指向 JDK 21。

## 2. 两种本地运行方式

### 隔离联调，不接业务库

在 `backend-spring` 执行：

```bash
java -jar target/shotting-booking-1.0.0.jar --spring.profiles.active=integration
```

另一个终端在 `frontend` 执行 `npm run dev:integration`，浏览器访问 `http://127.0.0.1:5174`；后端为 `127.0.0.1:18080`。

integration 使用 H2 内存库、`create-drop`、显式 mock 身份与测试排班，重启数据消失。教练测试身份 code 为 `integration-admin`，仍需到岗操作。真实用户和提醒送达不能用 mock 身份验收。不要将这一模式的数据源覆盖为业务库。

### 本地 PostgreSQL，保留数据

先在独立本地开发数据库执行 `backend-spring/scripts/schema-postgresql.sql`。可选执行 `scripts/init.sql` 导入示例；生产不导入。配置 `DB_URL`、`DB_USER`、`DB_PASSWORD`，然后在 `backend-spring` 执行：

```bash
bash scripts/dev-local.sh
```

脚本启用 local profile、mock 登录和 `validate`，默认监听 `127.0.0.1:8080`。没有 JWT_SECRET 时生成仅本次运行的临时密钥，重启后需重新登录。前端本地 `.env.local` 配置：

```dotenv
VITE_API_BASE_URL=http://127.0.0.1:8080
VITE_ENABLE_MOCK_LOGIN=true
VITE_AUTH_MODE=disabled
```

随后运行 `npm run dev:h5`。`.env.local` 不入仓。PostgreSQL 的 database 与 schema 是两层概念，当前 schema 始终为 `"ynu-shooting"`，不要混用 `public`。

## 3. 当前服务器布局与配置

以下为已有部署约定，不代表本次重新连接服务器核实在线状态：

| 项目 | 路径／值 |
| --- | --- |
| 应用服务 | systemd `ynu-shooting` |
| 运行 JAR | `/opt/ynu-shooting/backend.jar` |
| 环境文件 | `/etc/ynu-shooting/backend.env` |
| 外部配置 | `/etc/ynu-shooting/application-server.yml` |
| 数据库／应用账号 | `ynu_shooting`／`ynu_app` |
| schema | `"ynu-shooting"` |
| 备份 | `/var/backups/ynu-shooting/` |
| 上传工作目录 | `/home/ubuntu/ynu-deploy/` |
| 应用监听 | `127.0.0.1:8080`，由 Nginx 提供外部入口 |

必要配置：`DB_URL`、`DB_USER`、`DB_PASSWORD`、`JWT_SECRET`、`WECHAT_APP_ID`、`WECHAT_APP_SECRET`。JWT_SECRET 使用独立随机密钥并保持稳定；生产使用 wechat 身份与 `validate`。教练自助开通另需 `COACH_INVITE_CODE`，由负责人保管。

微信提醒可配置：

| 配置 | 含义 |
| --- | --- |
| `WECHAT_REMINDERS_ENABLED` | 默认 false，启用后才扫描队列 |
| `WECHAT_REMINDERS_STATE` | developer／trial／formal，消息打开的小程序版本 |
| `WECHAT_REMINDERS_LOCATION` | 场地地址 |
| `WECHAT_TRAINING_TEMPLATE_ID`／`WECHAT_DUTY_TEMPLATE_ID` | 两类提醒模板 |
| `WECHAT_TRAINING_FIELDS`／`WECHAT_DUTY_FIELDS` | 模板字段映射 JSON |

当前提前时间 15 分钟写在应用配置 `wechat-reminders.lead-minutes` 中。服务复用已有微信 AppID／AppSecret，不需要把密钥交给前端。

提醒配置工具为源码中的 `backend-spring/deploy/configure-wechat-reminders.sh`，复制到服务器后按实际测试版本执行，例如 `sudo bash configure-wechat-reminders.sh developer`。此脚本会恢复为本项目已提供的模板和地址并重启服务；已有正确配置无需重复执行，不能用它覆盖后续自行更改的模板。

## 4. 构建和升级

### 已有混合成绩结构的服务器

从仓库根目录执行：

```bash
python3 backend-spring/scripts/package-coach-daily.py
```

前提是已执行 JDK 21 `mvn verify`。当前代码包含[教员历史训练补录](教员历史训练补录.md)和[学员按日历史成绩](学员按日历史成绩.md)。按日视图本身无新增结构，包内保留历史补录兼容迁移；操作细节见[服务器补丁说明](学员按日历史成绩-服务器补丁.md)。生成 `dist/ynu-personal-history-20260927.tar.gz` 和校验文件。脚本自动创建输出目录，文件使用明确清单打包。该固定名字表示本版本交付批次；重新打包会覆盖本地同名产物，保存所部署包的实际哈希以区分。

上传后在服务器执行：

```bash
cd /home/ubuntu/ynu-deploy
sha256sum -c ynu-personal-history-20260927.tar.gz.sha256
tar -xzf ynu-personal-history-20260927.tar.gz
cd ynu-personal-history-20260927
sudo bash upgrade-coach-daily.sh
```

脚本校验包内 SHA256SUMS，检查混合模式前置结构，备份 JAR 和数据库，兼容性补齐提醒表、迁移历史补录结构，安装并检查 API；保留已有环境配置。服务会短暂停止。失败时仅在确认没有历史补录数据的情况下恢复旧 JAR；已有补录或查询失败则保持服务停止并提示人工处理。不自动覆盖恢复数据库。

更早数据库不能跳过前置迁移，见[数据库设计](../backend-spring/docs/database-schema.md)。混合模式迁移改变旧程序兼容性，不能把它当作普通 JAR 热替换处理。

### 全新服务器

运行 `python3 backend-spring/scripts/package-server.py` 生成首次安装包，按包内 README／[首次部署说明](../backend-spring/deploy/README.md)完成数据库、账号、systemd 与配置。当前完整 SQL 为 13 表，第一次安装不执行旧版本的增量修补来代替建表，也不导入演示用户。

### 小程序更新

团队测试：在 `frontend` 执行 `npm run build:mp-weixin:teamtest`，开发者工具导入 `frontend/dist/teamtest/mp-weixin`。该预设使用项目当前 HTTP 测试入口和真实微信身份，仍需手机调试环境，不能据此宣称正常上线。

正常发布配置放在不入仓的 `frontend/.env.production.local`：

```dotenv
VITE_API_BASE_URL=https://your-domain.example/ynu-shooting
VITE_ENABLE_MOCK_LOGIN=false
VITE_AUTH_MODE=wechat
```

替换为实际已配置域名，核对 `src/manifest.json` 的微信 AppID，运行 `npm run build:mp-weixin`，导入 `frontend/dist/build/mp-weixin`。微信上传、设体验版、审核、正式发布分别操作。修改后端不会自动更新手机前端。

不要为了订阅提醒去修改“小程序代码上传”IP 白名单。若微信接口明确报 `40164`，再检查接口级限制和服务器出口 IP。域名合法性、API IP 白名单和代码上传白名单是不同配置。

## 5. 最短验收与排障

升级后检查：

```bash
sudo systemctl status ynu-shooting --no-pager
sudo journalctl -u ynu-shooting --since '10 minutes ago' --no-pager
sha256sum /opt/ynu-shooting/backend.jar
curl --noproxy '*' --fail --get --data-urlencode "date=$(TZ=Asia/Shanghai date +%F)" http://127.0.0.1:8080/api/bookings/slots
```

返回 `code=0` 只能证明接口响应；无排班导致 available=0 属于正常业务状态。

真机至少验证：身份／资料、教练排班到岗、预约签到、使用中设备的后续预约、当前冲突保护、混合轮次结算、补登／恢复、按日筛选与更正、本人训练与值班消息送达及跳转。

提醒排查只查状态，不输出凭证：

```bash
sudo -u postgres psql -X -d ynu_shooting -c 'SELECT id,kind,target_id,status,scheduled_at,sent_at,attempts,last_code FROM "ynu-shooting".wechat_reminders ORDER BY id DESC LIMIT 20;'
```

- PENDING：待发送，核对时段和扫描服务；SKIPPED：业务不再需要或已过开始时间。
- SENT：微信接口接受，仍需手机确认；UNKNOWN：结果不确定，不盲目补发。
- 43101：订阅权限／次数不足；40037／47003：模板或字段问题。
- TOKEN_UNAVAILABLE：凭证获取失败；核对服务端配置和网络。当前此错误码未细分所有上游原因，不能单凭它认定是 IP 白名单问题。

日志、数据库查询和截图可能包含成员资料，分享前按实际内容遮盖；真实 AppSecret、数据库密码、邀请码及 JWT 密钥不进入仓库。

## 6. 备份、回退与 Git 版本

- 当前有升级前 `pg_dump` 和旧 JAR 备份，不等于已有周期备份平台或异地恢复保障。
- 近期可用备份和运行配置应保留；上传目录中的旧解压包不是运行程序本体。
- 恢复数据库会影响备份后的业务数据，必须依据故障与明确恢复方案操作；不把清空数据当作常规修复。
- 源码版本为 main 分支和 `v1.0.0` 标签；标签标识源代码基线，不是服务器部署成功回执。
- 提交前执行前后端检查，审阅 `git diff --cached` 和忽略规则，确认没有真实环境文件、数据库、备份或构建目录。
- 首次发布不附带真实运行数据、不自动发布 GitHub Release 附件；部署包在本地生成。
- 后续每次实际部署记录提交 SHA、JAR 哈希、迁移脚本、备份目录、前端版本及真机结果，避免仅用固定包名判断版本。
