# 微信训练与值班提醒

日期：2026-09-26。用户已确认前一版“教练成绩更正、删除输入提示、过往训练视图”真机测试通过。本次微信提醒为新增版本，已完成本地实现与验证，尚未部署或真实微信送达验收。

## 已确定的规则

- 队员训练和教练值班都在开始前 **15 分钟**提醒一次。服务器每 15 秒检查待发送记录，因此正常触发有一个轮询周期内的偏差；不依赖成员保持小程序打开。
- 成员在预约成功提示或“预约 → 我的预约”点击“订阅本次微信提醒”，并在微信弹窗中允许。教练在“我的 → 我的值班时间”中，给自己的每一个值班时段单独订阅。
- 当前按训练和值班共用用户提供的活动提醒模板配置。教练活动名称使用“射击场值班”；两类模板可分别配置，后续可以替换。
- 每次订阅仅安排当前预约／值班的一条提醒；不会把一次同意解释为所有未来时段永久授权。拒绝订阅不影响预约和排班，可单独取消尚未进入发送流程的提醒。
- 取消预约、已签到、已开始或结束训练、不再是教练、已到岗、删除排班、时段开始后，不再发送催到场提醒。发送前重新读取业务状态；发送流程开始后，已提交给微信的消息无法撤回。
- 在开始前不足 15 分钟才订阅时，下一轮检查尽快发送；开始后不补发过时提醒。
- 同一预约／值班只有一条提醒记录。成功发送后不重复；明确的临时错误最多尝试三次，间隔 30 秒且不超过开始时间。网络超时或发送中进程中断可能已经送达，标记为待确认，不盲目重发。

## 微信后台配置步骤

1. 登录 [微信公众平台](https://mp.weixin.qq.com/)，确认当前账号就是本小程序。
2. 在“功能 → 订阅消息 → 我的模板”确认上述模板存在，字段编号与本文件完全一致。
3. 无需为提醒功能修改“小程序代码上传”的 IP 白名单。若接口确实返回 `40164 invalid ip not in whitelist`，再检查对应接口的 IP 限制并配置实际服务器出口地址；没有启用接口限制时，不将其列为必做步骤。接口 IP 限制、合法请求域名与代码上传白名单分别管理。
4. 选择消息点击后打开的版本：`trial` 是体验版，`developer` 是开发版，`formal` 是正式版。相应微信账号须有目标版本的访问资格。本次团队测试默认采用 `trial`，不是正式发布。
5. 微信消息是否弹出通知还受成员的微信及手机通知设置影响；订阅成功和服务器成功提交都不能替代真机确认送达。

## 服务器部署与启用

更新包：`dist/ynu-wechat-reminders-20260926.tar.gz`。

本包包含本次提醒功能及此前教练成绩管理等功能。升级脚本先检查当前混合模式结构、备份 JAR 与数据库，然后新增 `wechat_reminders` 提醒队列表并替换程序。迁移可以重复执行，不改变现有预约、排班、身份与成绩表的数据。失败时恢复旧 JAR，不恢复覆盖数据库；新增的独立提醒表可与旧版本共存。

上传至 `/home/ubuntu/ynu-deploy` 后执行：

```bash
cd /home/ubuntu/ynu-deploy
tar -xzf ynu-wechat-reminders-20260926.tar.gz
cd ynu-wechat-reminders-20260926
sudo bash upgrade-wechat-reminders.sh
sudo bash configure-wechat-reminders.sh trial
```

第一条脚本负责更新程序和数据库；第二条脚本备份 `/etc/ynu-shooting/backend.env`，写入本次已给出的模板、地址和启用开关，保留微信登录密钥、数据库密钥、邀请码等其他配置，再重启并检查后端。配置失败会恢复原环境文件。

如使用微信开发者工具预览开发版，将最后一个参数改为 `developer`；未来正式版发布后再执行 `sudo bash configure-wechat-reminders.sh formal`。本次未提交微信审核或正式发布。

后端默认不开启提醒，直到启用脚本成功执行。若已经另外修改模板配置，重新运行启用脚本会将提醒相关配置恢复为本包的模板与地址。

前端仍使用 `frontend/dist/teamtest/mp-weixin`，在微信开发者工具重新编译并上传／预览，确保成员手机使用新版本。

## 真机验收

1. 预约一个尚未开始的训练时段，点击订阅并允许，看到“已安排提醒”。教练给本人对应值班时段也订阅一次。
2. 退出小程序，等待开始前 15 分钟，确认双方微信服务通知中的名称、起止时间、地点正确。
3. 点击通知，队员进入“我的预约”，教练进入对应日期的值班列表。
4. 新建另一条预约或值班，订阅后取消预约／排班，确认不再收到该时段提醒。提前签到或到岗也不再催到场。
5. 拒绝订阅，确认仍能正常预约／排班，且页面没有误报提醒已经安排。
6. 开始前不足 15 分钟再订阅时，会在下一轮检查尽快发出，可用于快速验证；已签到或已到岗的记录不适合做此测试。

## 排查

数据库中的 `wechat_reminders` 保留提醒状态、计划时间、尝试次数和结果码；该表不保存 AppSecret 或访问凭证。以下命令只查看最近状态，不显示密钥：

```bash
sudo -u postgres psql -X -d ynu_shooting -c 'SELECT id,kind,target_id,status,scheduled_at,sent_at,attempts,last_code FROM "ynu-shooting".wechat_reminders ORDER BY id DESC LIMIT 20;'
sudo journalctl -u ynu-shooting --since '30 minutes ago' --no-pager
```

- `SENT`：微信接口返回成功，仍需真机确认服务通知。
- `43101`：用户未订阅、订阅次数已用完或权限不足，需要本人重新订阅。
- `40037` / `47003`：模板 ID 或字段配置问题，检查后台模板及字段编号。
- `TOKEN_UNAVAILABLE`：微信访问凭证获取失败，核对服务器 IP 白名单及既有 AppID / AppSecret；不在日志中输出敏感响应。
- `UNKNOWN` / `DELIVERY_UNCERTAIN` / `INTERRUPTED_DELIVERY`：发送结果不确定，不会自动重发同一条提醒。
- `SKIPPED`：业务已取消、已到场或开始时间已过，正常跳过。
