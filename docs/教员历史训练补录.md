# 教员历史训练补录

2026-09-27，基于 v1.0.0 的功能增量。当前为本地实现和验证；未执行服务器部署或微信上传。

## 使用入口与业务规则

「我的 → 学员成绩管理」日期列表顶部新增「补录历史训练」。通过姓名或学号选择已登录并完善资料的成员，填写枪种、北京时间开始／结束时间，并逐轮录入分组总成绩。教员自身也是可训练成员，可以被选择。

- 每条历史训练包含 1–100 个实际轮次；轮数就是填写的轮次数，不单设“实际轮数”和“已录成绩轮数”。每轮成绩必填，零分可保存。
- 同次训练可交替登记决赛、资格赛；延续每发最高 10 环、分组总分最多一位小数的既有规则。
- 开始时间不得早于 1900 年，结束必须晚于开始且不能晚于当前时间；允许跨日。累计时长按起止时间计算，沿用分钟显示（不足一分钟记一分钟）。
- 保存后打开单次训练详情，返回可查看当日排名。按开始日期归属，每位成员同枪种、同赛制取当天最高一轮，同分并列；各轮保留在详情中。
- 个人训练历史和综合榜同步纳入已发布成绩。综合榜时间口径沿用 `scores.recorded_at`，本功能将其设为历史训练结束时间，避免补录旧成绩被视为今天训练。
- 标记“教员补录”，记录补录教员和补录时间；教员可通过现有更正入口修改分组成绩。当前不提供修改已保存起止时间／学员／枪种、删除历史训练的入口。
- 学员可查看本人的补录成绩，但不能自行增加轮次、恢复或结束补录训练；成绩有误联系教员更正。
- 历史补录独立保存，不创建预约、不占用设备或预约额度、不要求教员排班、不产生微信到场提醒。

## API 与数据变更

- `GET /api/coach/training/members?search=...&page=0`：教员搜索成员，返回姓名和学号，每页 20 条；空搜索返回空列表。
- `POST /api/coach/training/history`：教员一次提交整场训练；请求为 `requestKey`、`userId`、`weapon`、`startedAt`、`endedAt`、`rounds`，每轮含 `mode` 和 `groupTotals`。
- 请求键保障网络重试不重复新增；原始内容摘要用于拒绝同键不同内容。训练、轮次、最高成绩与审计在同一事务提交。
- `training_sessions.booking_id`／`device_id` 对历史补录允许为空；新增 `historical_weapon`、`recorded_by_user_id`、`history_request_key`、`history_request_hash`。普通训练仍由 SQL 约束要求关联预约和设备。
- 无新增业务表；仍为 13 表，新增补录教员外键后共 17 个物理外键。
- 审计动作 `CREATE_HISTORICAL_TRAINING` 保存操作者、学员、原始输入和生成的训练 ID。成绩更正继续使用原有审计。

## 构建与升级

使用 Java 21 在 `backend-spring` 执行 `mvn verify`；前端执行 `npm test`、`npm run build:mp-weixin:teamtest`。

已有 v1.0.0 服务器需执行新增的 `backend-spring/scripts/migrate-historical-training.sql`，不能只换 JAR。全新安装使用已更新的 `schema-postgresql.sql`。

兼容保留已有打包和升级脚本入口。从仓库根目录执行：

```bash
python3 backend-spring/scripts/package-coach-daily.py
```

本次产物为 `dist/ynu-coach-history-20260927.tar.gz`，内含 JAR、提醒及历史补录迁移、校验文件、`BUILD-INFO.json` 和本文；构建信息记录源码提交、工作区状态、打包时间及 JAR 哈希。上传解压后在包目录执行：

```bash
sudo bash upgrade-coach-daily.sh
```

脚本停止服务、备份 JAR 和数据库，执行迁移并启动验证。若已有历史补录数据或无法核实其状态，失败时保持服务停止，避免回退到无法读取补录记录的旧 JAR。首次迁移尚无补录数据时可恢复旧 JAR。

一旦保存了历史补录，旧版 JAR 不兼容其无预约／设备的数据结构。不得单独换回旧 JAR；需要先确定程序与数据配套恢复方案。迁移不删除原数据，不重算原成绩。

小程序导入 `frontend/dist/teamtest/mp-weixin`。此预设仍为团队测试配置，正常发布要求见开发部署文档。
