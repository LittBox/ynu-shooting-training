# 设备使用中仍可预约后续时段

日期：2026-09-26。已完成本地修复、回归测试和打包，尚未部署到服务器或进行本次真机验收。

## 问题与修复

设备开始训练后，全局状态变为 `IN_USE`。原先后端创建预约、查询时段以及前端日历都把该状态当成不可预约，错误地关闭了该设备所有未来时段。

现在分别判断未来预约与当前训练：

- 未来时段：设备没有维护或停用、该时段已有教练排班且设备没有有效预约，即可预约；设备当前正在使用不再阻止未来预约。用户原有的预约期限、每日／每周次数及同一时段冲突限制继续生效。
- 当前训练：设备仍在使用时，不能立即训练，也不能通过签到后“开始训练”挤占正在进行的训练。
- 每台设备的占用按日期和时段分别计算。同一未来时段并发预约仍只有一人可以成功。
- 首页设备仍显示真实的“使用中”状态。提交未来预约不会结束当前训练或将设备改为空闲。

例如，甲正在使用手枪进行 08:30–10:10 的训练，乙仍可以预约该手枪当天 10:30–12:10 或次日的空闲时段。

## 部署

更新包：`dist/ynu-booking-availability-20260926.tar.gz`。包括此前的成绩管理、历史记录和微信提醒功能，并保留服务器现有提醒开关、版本及模板配置。本次修复不需要重新运行提醒配置脚本。

上传到服务器 `/home/ubuntu/ynu-deploy` 后执行：

```bash
cd /home/ubuntu/ynu-deploy
tar -xzf ynu-booking-availability-20260926.tar.gz
cd ynu-booking-availability-20260926
sudo bash upgrade-booking-availability.sh
```

脚本校验文件哈希，备份旧 JAR 与数据库，确认原混合成绩结构，兼容性补齐提醒表，再安装新 JAR 并检查接口。失败会恢复旧 JAR；不会覆盖恢复数据库。已安装的提醒表不会被清空。更新过程中后端会短暂停止。

前端也必须更新：微信开发者工具重新编译本项目的 `frontend/dist/teamtest/mp-weixin`，扫码预览或上传体验版，确保测试手机打开本次新版本。只更新后端时，旧前端日历仍可能将设备使用中的未来时段隐藏。

## 验收

1. 教练为当前、后续及次日测试时段排班，并在当前时段到岗。
2. 甲开始一场训练并保持训练中。
3. 乙查看同一设备：当前不能立即训练；后续及次日无预约的已排班时段显示可预约，提交成功。
4. 丙预约乙已占用的未来时段，确认无法重复预约。
5. 检查甲仍处于训练中，未被乙的预约结束或释放设备。
6. 甲结束训练后，后续预约仍正常保留；乙在允许的时间签到并开始训练。
