# 预约界面：设计与接入说明

## 范围与视觉

本次完成预约页及其必要登录、身份登记入口。参考图中的日历阅读方式用于三日日程；固定六个时段沿用项目需求，不引入候补、信用分或推荐功能。

用户确认的色板通过 `App.vue` 的语义变量统一管理：

| 颜色 | 语义 | 用途 |
| --- | --- | --- |
| `#3d4a5d` | 主文字、深色操作 | 标题、主按钮 |
| `#707f97` | 主色、次级文字 | 选中日期、我的预约、设备状态、辅助信息 |
| `#b1b7c5` | 边界 | 分隔、描边、未选中的控件 |
| `#f0f1f7` | 浅底色 | 页面、日程块、确认摘要 |

白色为承载内容的中性表面。状态同时用文字、实底、边线和虚线表达。靶心由 CSS 绘制，不增加图片下载。预约页复用现有 NavBar、原生 TabBar，并适配安全区域和减少动画偏好。

## 模块边界

- `domain/booking.js`：六个标准时段、北京时间、日期窗口、自然周配额、状态与取消等级；纯函数，可脱离 UI 验证。
- `services/request.js`：环境地址、JWT、超时、业务错误；不操作 UI。401 只清理属于当前失败请求的旧会话。
- `services/booking.js`：实际后端路径与 DTO 投影；余量列表不携带身份信息，时段详情使用后端按权限投影的独立 DTO。
- `composables/useBooking.js`：刷新、请求版本号、选择、提交与页面生命周期；服务参数可以替换，便于测试和未来适配。
- `components/booking/`：日期栏、日程表、设备确认和个人记录；通过 props / emits 传递意图，不直接请求接口。
- `pages/booking/booking.vue`：页面组合、须知、操作确认与反馈。
- `services/auth.js` / `pages/login/login.vue`：必要的登录和实名登记。生产构建禁用开发模拟身份。

新增设备由接口驱动，无设备数量或 ID 奇偶数假设。更换接口时修改服务层；调整业务规则时修改领域层并同步后端权威配置；更换主题时修改设计 Token。

## 已接入的交互

1. 今天至第 7 天（含边界，共 8 个日期）可查看，跨月、跨年按北京时间计算。
2. 三日并排、日期跳转、前后翻页、回到今天、气手枪/气步枪筛选。
3. 六个标准时段；已开始、无开放设备、约满与个人预约分别表达。
4. 点击任意日程格（含已约满、已开始、未开放）查看该时段的设备与预约学员，再从可预约设备进入确认弹层。未登录先登录，返回后保留选择；未实名进入登记。
5. 提交前重新获取设备余量和本人记录，校验每天 3 场、自然周 10 场、重复时段和时效。按钮提交期间锁定。
6. 仅收到后端成功响应才显示成功。失败保留上下文、展示原因并刷新；刷新失败时撤下旧余量。
7. 我的预约可查看历史、分级取消、在开始前 30 分钟至开始后 10 分钟内签到。取消和签到都有明确确认。
8. 页面可见时每 30 秒刷新；离开暂停，返回重新拉取。手动刷新和下拉刷新可用。此版本没有把轮询标注成 WebSocket 实时连接。
9. 首页可通过一次性 `booking-device-filter` / `booking-view` 存储值跳入指定设备类型或个人预约视图，读取后删除。

## 环境配置

可将下列配置写入 `frontend/.env.local`（不应提交）：

```dotenv
VITE_API_BASE_URL=http://localhost:8080
# 仅本地联调启用，生产构建会禁用此开关
VITE_ENABLE_MOCK_LOGIN=true
```

以下为之前联调记录；2026-09-25 起，后端已实现微信兑换，并将开发登录限制在显式本地 profile，最新说明见 backend-spring/README.md。旧版 `resolveOpenid` 曾将 code 直接作为测试身份。前端默认关闭登录创建入口，允许游客浏览；显式开启开发联调后可完成真实本地 API 流程，页面明确标注测试身份。后端接入微信 `jscode2session` 后，才配置 `VITE_AUTH_MODE=wechat`。

真机的 API 地址须指向可访问的服务器，不能使用手机自身的 localhost。正式上线需配置小程序合法 HTTPS 域名。H5 使用现有后端 CORS 设置。

实际接口为：`GET /api/bookings/slots?date=...`、`GET /api/bookings/me`、`POST /api/bookings`、`POST /api/bookings/{id}/cancel`、`POST /api/bookings/{id}/checkin`，不是计划文档中的 `/my`。

## 联调修复及现有限制

为使预约流程真正可运行，修复了 User / Profile / Booking / CancellationLog 构建器丢失默认值、Profile 的 MapsId 新建方式，以及 Auth 接口直接序列化双向实体的问题。Auth 接口返回明确的会话 DTO。修复两处阻碍后端编译的 BusinessException 参数类型错误。时段接口补充设备状态，并与创建预约一起拒绝已开始时段和维护、停用、使用中的设备。

本次没有宣称后端已满足完整生产验收：此项为之前版本限制；本轮已补齐排班与可训练时间校验、数据库并发占位和微信兑换实现，真实微信验收仍需有效凭据。提交前重读与按钮锁定不能替代服务端并发锁。后续上线前需完成这些约束。

联调期间发现本地 `application.yml` 同时声明 H2 与 PostgreSQL 两段 `spring.datasource`，会引发重复键错误。保留工作区数据库调整，回归测试使用独立 `booking-flow-test.properties`，避免触碰已有持久数据。本轮已合并为唯一数据源配置，PostgreSQL 通过环境变量提供；integration profile 使用独立内存库。

## 日程详情与现场协调（2026-09-25）

- 新接口：`GET /api/bookings/slots/details?date=YYYY-MM-DD&slotId=S1`。按设备返回预约学员、待签到 / 已签到 / 训练中 / 已完成 / 已爽约；取消记录不作为占用人展示。
- 游客只看设备安排；已登录学员看昵称；教练沿用 `admin / superadmin`，查看姓名及学号。手机号、openid、实体关联不返回。角色以数据库当前值为准，非法 token 返回 401，不降级返回实名数据。
- 教练读取名单写入 `VIEW_SLOT_ROSTER` 审计，记录查询日期和时段。详情不实现消息发送或代替他人改约；现场协调后仍由本人操作预约。
- `useSlotDetails` 单独负责详情查询、30 秒刷新、错误和生命周期；`SlotDetailSheet` 只展示 props 并发出意图，与预约写入解耦。关闭、离开页面和切换日程会使旧请求失效；刷新失败清除旧名单，避免把旧状态当作当前安排。
- 沿用日程设备类型筛选。从设备详情进入确认时预选该设备，提交前仍重新校验设备和预约限额。配色继续使用统一的四个主题 Token。
- 验证：前端 28 项测试通过，H5 / 微信小程序构建通过；后端 23 项测试通过。新增测试覆盖满场及过往时段查询、异步响应竞争、账户切换、失败清理、三种角色投影、权限撤销、审计、取消过滤与训练状态。

浏览器联调：390×844 手机尺寸验证了满场详情中两台设备与演示昵称的对应关系、游客与登录后信息变化、以及选择步枪设备后确认弹层正确预选步枪；短屏使用整层滚动，避免设备区域被压缩为零。当前本地演示使用临时内存库中的虚构学员。
