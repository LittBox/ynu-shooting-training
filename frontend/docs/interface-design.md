# 学员端界面与验证

## 页面范围

学员端包含首页、训练预约、排行榜、个人中心、登录与身份登记五个页面，均已注册路由。视觉采用简约线条风，沿用当前工作区灰蓝色语义变量、细边框、留白与线条图标。首页保留两个枪种入口和已有设备图片。

| 页面 | 行为 |
| --- | --- |
| 首页 | 查询今日可约时段数量；按气手枪或气步枪进入预约；登录与个人中心入口；下拉刷新 |
| 预约 | 日期与设备筛选、三日日程、确认弹窗、提交结果、个人预约、取消、签到；细节见 booking-design.md |
| 排行榜 | 枪种、资格赛/决赛、最佳/近五次均值/进步、性别筛选；加载、未登录、服务错误、空榜和成绩列表 |
| 个人中心 | 账号状态、身份登记提醒、真实预约统计、下一场训练、预约与签到入口、规则说明、退出登录 |
| 登录 | 微信/开发环境能力开关、身份登记必填与手机号验证、游客浏览、返回原页面 |

排行榜不再内置虚构选手、学号或成绩。请求结果仅投影到昵称/化名、名次、环数、日期等显示字段。个人中心获取失败时显示未知统计值，不用零掩盖错误。预约只在实际创建接口成功后显示成功。

## 接口与环境

预约及登录的实际接口、配置项和现有后端限制见 [预约设计与接入说明](booking-design.md) 与 `.env.example`。

排行榜依照 `.specify/leaderboard-redesign.md` 预留 `GET /api/leaderboard`，参数为 `weapon/event/metric/gender/limit`。后端已实现该接口及 BEST/AVG5/PB30D/IMPROVE，使用真实已完成训练的管理员录入成绩；联调见 integration-validation.md。

服务端已接入 code-to-session 兑换；正式微信登录仍需部署方配置 AppID/AppSecret 并完成真机验收。前端沿用 `services/auth.js` 的环境开关，不能把开发模拟登录视为生产微信鉴权。

- `node --test tests/*.test.mjs`：20 项通过。包含时区、预约配额、截止与签到边界、过期请求、失败刷新、重复提交，以及提交成功/失败、余量变化、配额重读、游客/未实名跳转。
- H5 与微信小程序生产构建通过；构建仍提示工具链 Sass legacy API 弃用警告，不影响本次编译。

- 浏览器 320 × 740：排行榜内容无横向溢出，赛事和排名指标切换正确。
- 修正 H5 原生按钮默认伪元素边框导致的重复描边。

浏览器验证时本地业务服务未连接，因此本轮 UI 检查未执行实际数据库预约写入；提交分支通过服务替身单元测试验证。微信小程序已编译，但未在真机上完成验收。
